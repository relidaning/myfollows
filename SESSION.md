# Sessions

## 2026-07-29 — Replace VNC-based YouTube login with a real desktop Chromium window
Removed the in-container Xvfb+x11vnc+noVNC+matchbox virtual-display stack (deleted `douyin-mcp/start.sh`, stripped VNC packages/ports from `Dockerfile`/`docker-compose.yml`) and replaced it with mounting the host's `/tmp/.X11-unix` socket + `DISPLAY=:0` into the container, so clicking "Login to YouTube" launches a headed Chromium that pops up directly on the host desktop — chosen over a real Google OAuth app (rejected: would require a Google Cloud project, drop the subscriptions-feed scraping approach for the Data API, and force weekly re-auth without app verification). Updated `youtube.py`, `server.py`, `ui.html`, README, and CLAUDE.md accordingly; this is now documented as "Option A" in README alongside the existing cookie-import path ("Option B") from the prior session. Session ended mid-`docker compose up -d --build` verification, so the rebuild/end-to-end test wasn't confirmed complete within the transcript.

## 2026-07-29 — YouTube cookie-import login, first real sync fixes, container port collision
Replaced the noVNC-driven YouTube login flow's embedded modal with a proper new-tab open, then (per user request to avoid VNC/remote-control entirely) built `scripts/import_youtube_cookies.py` to lift live session cookies from the user's local Chrome (decrypted via the Secret Service D-Bus keyring) into `data/youtube_storage_state.json`, plus a `/api/youtube/reload_session` endpoint so the running container picks up a re-imported session without a restart. This was the first real end-to-end YouTube sync ever attempted, which surfaced several pre-existing bugs: a `pw.chromium.new_context()` vs `browser.new_context()` typo, stale DOM selectors from a YouTube redesign (`_scrape_subscriptions`), unbounded scrolling that loaded hundreds of cards regardless of `limit` (causing multi-minute hangs/OOM-style restarts), a stale `/tmp/.X99-lock` blocking Xvfb on in-place container restarts, and an unrelated second container (`douyin-follows-douyin-mcp-1`, a different project) squatting host port 8082 via `network_mode: host` and intermittently answering this app's requests — stopped after user confirmation. Confirmed a full sync (90 videos, 33 creators, ~12.6s) working end-to-end afterward; README's "YouTube login" section now documents cookie-import as "Option B" alongside the VNC flow.
